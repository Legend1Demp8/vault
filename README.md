# HashiCorp Vault — 3-Node Raft Cluster (Docker)

Отказоустойчивый трехнодовый кластер **HashiCorp Vault** в Docker Compose на базе встроенного хранилища **Integrated Storage (Raft)** с автоматическим выпуском и продлением самоподписанных TLS-сертификатов через сервис `nip.io`.

## Особенности архитектуры

* **Кластер из 3 нод (`node1`, `node2`, `node3`).** Обеспечивает кворум и отказоустойчивость: при выходе из строя одной ноды кластер автоматически выбирает нового лидера и продолжает работу без потери данных.
* **Схема инициализации 3 из 5 (Shamir's Secret Sharing).** Главный ключ шифрования при инициализации делится на 5 частей, для разблокировки (`unseal`) требуются любые 3 ключа.
* **Автоматический PKI и конфигурирование (`vault-cert-gen`).** Вспомогательный контейнер на базе Alpine при запуске:
  * Генерирует корневой центр сертификации (`certs/ca/ca.crt`).
  * Выпускает индивидуальные TLS-сертификаты для каждой ноды сроком на **365 дней** с привязкой к доменам `vault{1..3}.<HOST_IP>.nip.io` (не требует правки `/etc/hosts`).
  * Автоматически перевыпускает сертификаты, если до истечения их срока действия осталось менее **30 дней**.
  * Генерирует конфигурационные файлы `node{1..3}/config/vault.hcl` из единого шаблона `vault.hcl.tpl`.
* **Изоляция ключей.** Каждая нода монтирует только свою подпапку (`certs/vault1`, `certs/vault2`, `certs/vault3`) в режиме `read-only` и не имеет доступа к закрытым ключам соседей или корневого CA.

## Структура проекта

```text
.
├── .env                  # Файл переменных окружения
├── .gitignore            # Исключения Git (сертификаты, базы Raft, .env, конфиги с IP)
├── docker-compose.yml    # Описание сервисов и внутренней сети с DNS-алиасами
├── generate-certs.sh     # Скрипт генерации TLS-сертификатов и конфигов из шаблона
├── vault.hcl.tpl         # Универсальный шаблон конфигурации ноды Vault
├── certs/                # Сгенерированные сертификаты и ключи (не хранится в Git)
└── node{1..3}/
    ├── config/           # Сгенерированный vault.hcl для конкретной ноды
    └── data/             # База данных Vault и хранилище Raft (не хранится в Git)
```

## Настройка перед запуском

### 1. Подготовка переменных окружения (`.env`)

Клонируйте репозиторий

Перейдите в папку с проектом

Откройте `.env` и укажите **внутренний IP-адрес** вашего сервера в переменной `HOST_IP`:

```env
VAULT_VERSION=2.2.2
ALPINE_VERSION=3.24.4
HOST_IP=192.168.1.50
```

* `VAULT_VERSION` — закрепленная версия образа `hashicorp/vault`.
* `ALPINE_VERSION` — закрепленная версия образа `alpine` для init-контейнера.
* `HOST_IP` — единственный IP-адрес хоста без пробелов, на базе которого формируются домены `nip.io`.

### 2. Настройка прав доступа к директориям данных

Процесс Vault внутри контейнера запускается от непривилегированного пользователя `vault` (`UID 100`, `GID 1000`). Перед первым запуском выдайте ему права на папки `data`:

```bash
chown -R 100:1000 node1/data node2/data node3/data
```

## Запуск и сборка кластера

### 1. Старт контейнеров

```bash
docker compose up -d
```

Контейнер `vault-cert-gen` создаст сертификаты, сгенерирует файлы `vault.hcl` и завершится со статусом `Exited (0)`, после чего запустятся все три ноды Vault.

### 2. Инициализация первой ноды

Выполните инициализацию на `vault-node1`:

```bash
docker exec -it vault-node1 vault operator init
```

> **Важно:** Vault выведет **5 Unseal Keys** и **Initial Root Token**. Сохраните их в надежном менеджере паролей. Без любых 3 ключей распечатать кластер после перезагрузки будет невозможно.

### 3. Распечатывание (Unseal) всех нод

После запуска все ноды находятся в запечатанном состоянии (`Sealed: true`). Разблокируйте каждую ноду, выполнив команду ниже **по 3 раза подряд** (каждый раз вставляя новый ключ из 5 полученных):

```bash
# Распечатываем лидера (node1)
docker exec -it vault-node1 vault operator unseal

# Распечатываем реплики (после ввода 3-го ключа они сами подключатся к лидеру через retry_join)
docker exec -it vault-node2 vault operator unseal
docker exec -it vault-node3 vault operator unseal
```

### 4. Проверка состояния кластера

Авторизуйтесь с помощью `Initial Root Token` и проверьте список участников Raft:

```bash
docker exec -it vault-node1 vault login
docker exec -it vault-node1 vault operator raft list-peers
```

В выводе должны отобразиться три ноды (`node1`, `node2`, `node3`) со статусами `leader` и `follower`.

## Доступ к Web UI

Веб-интерфейс каждой ноды доступен по HTTPS (при первом входе примите предупреждение браузера о самоподписанном сертификате или импортируйте `certs/ca/ca.crt` в доверенные корневые центры ОС):

* **Node 1:** `https://vault1.<HOST_IP>.nip.io:8200`
* **Node 2:** `https://vault2.<HOST_IP>.nip.io:8202`
* **Node 3:** `https://vault3.<HOST_IP>.nip.io:8204`

## Эксплуатация и обслуживание

### Перезапуск контейнеров или сервера
При рестарте контейнеров ноды автоматически переходят в состояние `Sealed`. Для возврата в работу достаточно заново выполнить шаги `vault operator unseal` (ввести 3 ключа) на каждой ноде.

### Продление TLS-сертификатов
Скрипт `generate-certs.sh` проверяет срок действия сертификатов и перевыпускает их только если осталось меньше **30 дней**. Чтобы проверить и обновить сертификаты без перезагрузки нод и повторного ввода `unseal`-ключей:

```bash
docker compose restart cert-gen
docker kill -s SIGHUP vault-node1 vault-node2 vault-node3
```
